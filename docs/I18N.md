# Internationalisation

Languages: English (`en`), Hindi (`hi`, Devanagari), Punjabi (`pa`, Gurmukhi). Library: `i18next` + `react-i18next`.

## How it works
- Catalogues live in `artifacts/seedchain/src/i18n/locales/{en,hi,pa}/*.ts`, one file per area (`app`, `account`, `farmer`, `orders`, `admin`, `public`, `landing`, `shared`, `server`). `en` defines the shape; `hi` and `pa` are typed against it.
- `locales.test.ts` fails the build if any language is missing a key, has an empty value, or changes a `{{placeholder}}`.
- Choice order: saved choice (`localStorage` key `sc.lang`) -> browser language -> English. `<html lang>` follows it. Switching remounts the page tree, so helper-based labels refresh too.
- Dates, numbers, currency and units use the selected locale (`en-IN`, `hi-IN`, `pa-IN`). Fonts: Noto Sans Devanagari / Gurmukhi, with tighter letter-spacing rules for those scripts.
- Status/enum values (order and lot status, risk, event types, alert types, storage kinds, crops) are translated through `enums.*`; unknown values fall back to a readable form.
- **Server-authored sentences** (event reasons, risk factors, alert messages, weather conditions, data-source descriptions) are translated on the client by `lib/server-text.ts` using exact and pattern matches. Anything unrecognised, including text a farmer or admin typed, is shown exactly as stored.

## Deliberately not translated
Names, emails, lot/order codes, URLs, variety names (e.g. Kufri Jyoti), district and organisation names, audit-log action codes and JSON, and text users typed. The **printed QR label** (SVG/PNG/print) stays English because exported images cannot embed the Indic fonts reliably; the on-screen controls around it are translated.

## Adding a string
Add the key to `en/<area>.ts`, then to `hi` and `pa`; run `pnpm --filter @workspace/seedchain test`.

## Quality note
